# 直播守望 LiveWatch 2.8.0 · 稳定性优化版

本目录从 `release/LiveWatch-2.8-Windows10-11-x64` 还原，现已按《优化.md》完成稳定性与便携启动优化，可直接运行和修改。Python 后端、HTML/CSS/JavaScript 前端、原版桌面程序、Python/FFmpeg/WebView2 运行库、许可证和发布文档均已复制到项目根目录下，保留原有相对布局。原始 `release` 目录保留为对照副本。

## 用户交付

交付包为 `artifacts/LiveWatch-Optimized-Windows-x64.zip`，已内置 `tools/ffmpeg.exe`，无需下载 FFmpeg。完整解压后双击 `直播守望.exe`，首次自动下载并校验 Python、WebView2 到 EXE 同目录 `tools/`，随后打开本地桌面窗口。约需下载 307 MiB，支持取消、重试和断点续传；后续复用运行库。目标为 Windows 10 22H2 / Windows 11 x64（系统 .NET Framework 4.8）。详情见 [portable-delivery.md](portable-delivery.md)。

新版采用三态判定：明确开播、明确下播、无法判定。检测时显示醒目的旋转提示，超过所设置的请求超时时间仍未完成则进入失败恢复、显示“恢复中…”，超时立即释放检测名额，依次让其他房间先获得 1→2→4→8→1 次检测机会后重新排入；成功后清零退避并直接显示最新直播状态。检查异常不会结束直播或录制；已开播转下播需两次连续明确结果。列表保留最近确认状态并显示最近成功检查时间，错误与恢复过程记录在日志中。录制按任务独立管理，默认 30 分钟分段，媒体停滞后关闭旧连接、重新确认状态和取源，再创建新片段。最新交付说明见 [检测超时恢复与交付.md](检测超时恢复与交付.md)。

新增行为、验收数据和实际限制见 [优化交付与验证.md](优化交付与验证.md)。本 README 后面的构建和开发命令面向完整源码目录，轻量交付包无需执行。

高频监控确认抖音开播后，使用最多两路独立后台任务逐步补采本场开播时间，每秒最多新增一次补采，失败约一分钟后重试。确认下播后也会自动补采平台结束时间，未完成的历史场次在重启或下一场开播后继续补齐。取得后自动更新列表和本场 CSV；状态监控优先使用全局请求预算。监控列表默认使用约 44 像素紧凑行高，显示补采进度和时间来源。首次监控也查询可用的上一场时间。平时仅轮询直播状态，变化后更新对应列；两列各自保留最新一次值。平台时间缺失时展示带“检测”标记的本机观察时间，取得有效平台时间后补正并停止补采。

## 启动

- 桌面窗口：双击根目录 `start.cmd` 或 `直播守望.exe`。
- 开发服务：双击 `dev.cmd`；控制台会输出本机地址，在浏览器中打开即可查看页面。抖音内置登录等桌面桥接功能仍需桌面窗口。按 Ctrl+C 停止开发服务。
- 命令行（在本目录执行）：

```powershell
.\tools\python\python.exe .\run.py --version
.\tools\python\python.exe .\run.py --no-browser
```

根目录 `run.py` 是开发入口，默认将数据存入本项目根目录；可传 `--data-dir <其他目录>` 隔离数据。若使用隔离目录，需在设置中指定本项目 `tools/ffmpeg.exe` 的完整路径。直接运行 `app/run.py` 时应显式传入 `--data-dir`。

开发目录可复用已有 Python 3.12.10、FFmpeg 和 WebView2；轻量交付包首次点击 EXE 自动准备这些组件，系统需 .NET Framework 4.8。后端只依赖 Python 标准库，无需安装 pip 包。也可用正常安装的 Python 3.12 运行根目录 `run.py`。

## 性能说明

免安装版本直接执行 CPython、FFmpeg 和 WebView2，不存在每次运行解压整包的步骤。2026-11-21 的并发改造保留现有桌面窗口和 HTTP API，默认采用独立补位调度：慢房间和短暂故障补查不再阻塞本轮其余房间；仍可选择原整批模式。

新建配置默认启用高频状态模式：每房间检查完成后等待 8 秒、32 路总并发、4 路抖音状态并发、单次超时默认 4 秒、可设置为 2～60 秒，全局最多每秒派发 20 个探测任务（含复核和手动取源）。抖音单独默认每秒最多派发 2 个检查任务，均匀错开，开/下播时间补采与状态检查共享额度；该值是本地保守默认，不代表抖音公布的配额。高频状态检查把页面回退放到下一个受限派发时机；兼容取源可能在一次任务中发起多个 HTTP 请求。已有配置保留原有周期/并发值，同时应用新增抖音速率上限。周期、超时和1～64并发都可在设置页调整；高频模式不受旧的逐房间间隔与整轮等待影响。同一房间不会重入，慢房间不阻塞健康房间。手机观看身份隔离默认开启，监控请求不使用手机账号会话。

连续失败按房间退避并错峰；多个房间短时间共同失败时降低抖音速率，冷却后逐个试探，持续稳定才逐级提速。持续异常可重建探测进程和访客会话，最多每 10 分钟一次，保留直播场次、登录授权与录制任务。具体日志依据和验证见 [异常恢复与媒体设置.md](异常恢复与媒体设置.md)。复制源默认 FLV、比原画低一档实际可用画质；播放默认低两档，窗口随视频比例调整。默认值可在设置中修改；开启自动录制先选择画质和保存目录。本机登录授权永久保存、没有本地到期时间，平台撤销会话时仍需重新登录。

配置等待时间并不等于检测延迟；排队、请求、平台更新、下播复核和界面刷新都会增加时间。顶部展示实际检查间隔 P95，每房间详情显示实际间隔；检查失败时列表保留最近确认结果和成功时间，内部仍标为未知 / 过期。高频模式要求固定直播间地址或有效状态接口，账号/主页/短分享链接需先替换为固定房间地址。关闭高频模式后可使用原兼容探测（总并发1～16、抖音1～5），支持较慢的主页解析和完整元数据路径。容量估算、使用方法、真实能力边界和24小时长测命令见 [弱网150房间方案.md](弱网150房间方案.md)，本次执行结果见 [高频监控验收.md](高频监控验收.md)。

默认开启探测进程隔离，工作进程按需启动并复用，只负责网络检查；主进程集中维护 SQLite、直播场次和录制。检查超时或工作进程崩溃会回收该进程，下次检查按需重建；检查失败保留未知/最近确认状态，不当作下播。进程会增加内存开销，设置中可关闭隔离改用线程。状态 API 的 `monitor` 包含工作进程数、回收次数和超时次数，运行资源日志也记录这些数值。

录制器使用 FFmpeg `-c copy` 按关键帧分段保存；同时校验媒体时钟前进与文件增长，默认 30 秒无有效媒体则回收连接、重新取源续录。磁盘低于阈值时停止写入；任务、最后有效写入时间和恢复事件持久化，重启后先检查状态再恢复自动录制。Windows 后端崩溃时 Job Object 回收所属 FFmpeg，避免孤儿进程重复录制。录制主要受网络、磁盘和并发录制数量影响。内嵌播放器使用 `libx264` 软件转码（每路 2 线程、最大宽度 1280），打开多个画面可能增加 CPU 占用。监控频率还受到批次设置、网络和平台接口响应影响。还原后的源码可用于后续测量和有针对性的优化。

本轮没有新增 C++ 模块：已确认的瓶颈是调度等待与无法取消的网络系统调用，媒体处理已由原生 FFmpeg 完成。进程隔离解决故障范围与回收问题；平台空响应、限流或网络断开仍需要退避，不能靠更换语言保证成功率。后续仅在 CPU 分析确认热点后迁移对应模块。验证命令和边界见 [并发改造与验证.md](并发改造与验证.md)。
